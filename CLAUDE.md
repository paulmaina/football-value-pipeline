# Football value pipeline: notes for Claude

Read `docs/plan.md` first. It holds the current plan, the release rules and the decisions already made.

## Working rules

- **No production change without evidence.** Predictions, probabilities and shortlist logic change only after a candidate passes the release gate in `docs/plan.md`, and only through a reviewed PR. Reporting-only fixes may go in separate PRs.
- **The value shortlist's research model must stay independent of bookmaker odds.** Never feed odds, the published grid or market fits into it. Keep the odds-perturbation test passing.
- **The holdout (Eredivisie, Primeira Liga and Süper Lig, 16 Jan – 10 Oct 2026) is locked.** Don't run `evaluation_harness.py --declaration` or look at holdout scores while developing; each candidate can be scored once, and a frozen setup once per candidate. Develop on the development period; validation and retrospective periods have already been inspected.
- **The European holdout (UCL, 21 Jan 2025 – 12 Oct 2026) is locked the same way**, with its own ledger (`evaluation/european_holdout_ledger.json`). Don't run `--mode european --declaration`; develop on European development and validation (UEL only; see `docs/european-backtest.md`).
- **Pre-kickoff data only.** Anything graded or replayed must have been known before the match (see `performance_tracking.lead_checked`).
- **Bets are placed at Pinnacle only** (`shortlist_quote_policy.json`). That is separate from where a model's probabilities come from.
- Work on a branch and open a PR; don't push to `main`.

## Useful commands

```bash
pip install -r football_value_dev_requirements.txt
python -m pytest -q tests                                   # full suite (~5 min)
python evaluation_harness.py --output /tmp/eval             # development + validation, 8 leagues
python evaluation_diagnostics.py --run /tmp/eval --output evaluation/diagnostics # standing diagnostics from that run
python evaluation_harness.py --mode live --output /tmp/live # replay frozen forecasts since 5 Nov 2026
python evaluation_harness.py --mode parity --output /tmp/parity # research model: harness vs live inputs and probabilities
python evaluation_harness.py --mode european --output /tmp/europe # UCL/UEL results only, locked; CE baseline
python performance_tracking.py review --api-key-source environment && python workflow_checks.py reports
```

## Map

- `football_value_pipeline_v2_standalone.py`: forecasting pipeline (Dixon-Coles, market blend, published grid).
- `team_research.py`, `profit_shortlist.py`: the independent research model and the value shortlist. Research v5 (14 Nov 2026) prices domestic leagues with C6 (`research_low_score_sharpen.py`) and keeps v4 in shadow. Live fits: `research_c6_live_fits.json` (every known result, holdout period included, refreshed every second Monday by `.github/workflows/research-c6-fits.yml` via `scripts/build_research_c6_fits.py`). The harness's tested, holdout-free fits stay locked in `research_c6_fits.json`; the two differ by design. Research v6 (14 Nov 2026) prices UCL/UEL with CE3n (`research_ce3n.py`: v4's goal rates blended with domestic strength) and keeps CE (v4) in the same shadow columns. Live fits: `research_ce3n_live_fits.json` (league factors and domestic strengths from every known result, both holdout periods included; refreshed in the same workflow via `scripts/build_research_ce3n_fits.py`); tested fits locked in `research_ce3n_fits.json`. Live versions per scope come from `research_config.json` (domestic v5/v4, UCL/UEL v6/v4): rolling back v5 or v6 is switching that scope to v4, never reverting the release, so archived forecasts still replay.
- `research_monitoring.py`: v5's rollback trigger and holdout-league home-favourite check, and v6's rollback trigger (CE3n vs CE on graded European matches) with calibration slopes, in the weekly report.
- `price_edge_cagey_shortlist.py`, `narrow_margin.py`, `cagey_market_basis.py`: the cagey tier (market view). Its grid removes the bookmaker margin proportionally; `power` and `shin` exist behind a `method` argument for offline candidates only (plan Phase 3b), with their corrections in `narrow_margin_models/candidates/`, which nothing live reads. A correction is never applied to a grid it was not fitted on. D_pow2 (plan Phase 3b-2, offline only) is the power candidate whose model also carries a `one_x_two` block: the 1X2 set separately from the power quote (`narrow_margin.one_x_two_target`); a model without the block is corrected exactly as before. Registered as harness candidate `D_pow2` (`evaluation_harness.CAGEY_CANDIDATES`; only with `--cagey-candidates` or a declaration, so default runs are unchanged) and declared against D in `evaluation/declarations/cagey_dpow2_holdout.json` (criterion `calibration_and_point_estimates`). Scored once on 17 Nov 2026 (`evaluation/holdout_cagey_dpow2/`): passed, so the outcome is release; it is locked in the ledger (plan Phase 3b-3). Released for domestic leagues behind `cagey_correction_config.json` `cagey_correction_live` (`domestic` "D_pow2" or "D"; UCL/UEL "D" only), D in shadow; rollback trigger in `research_monitoring.cagey_rollback_check`; rolling back is setting the switch to "D", never reverting the release. Where D_pow2's power fit B fails its fit check, the fixture falls back to D, with D's grid and correction (`cagey_basis`, flagged in `cagey_correction_fallback`, counted in the weekly report); D_pow2's correction is never applied to another grid. Runs record the switch in their summary, and earlier runs replay under D.
- `master_shortlist.py`, `master_selection*.py`: the master shortlist.
- `performance_tracking.py`, `workflow_checks.py`: grading, reports and their validation. The dashboard, weekly files and price-edge report lead with closing-line value (`clv_report.py`), returns second, per pick and with one row per fixture (`performance/fixture_grades.csv`).
- `model_activity.py`: the append-only model activity log (`football_output_v2/model_activity/activity_log.jsonl`): releases, C6/CE3n refits, stale-fit warnings, rollback checks, switch changes and master fallbacks, written by the refit workflow, forecast runs and the review; shown in the performance workbook's Model Activity tab. Never edit or remove a line; `python model_activity.py backfill` is idempotent.
- `evaluation_harness.py`, `research_backtest.py`, `historical_benchmark.py`: offline evaluation; `european_results.py`: cached UCL/UEL results for the harness.
- `research_rate_calibration.py`: offline harness candidates C7 (fitted rate calibration on C0's Dixon-Coles goal rates, no last-ten form term, on C2's grid) and C8 (C7 plus a fitted Elo term from `elo_ratings.py`). Not live. C8 is the research candidate (Paul, 16 Nov 2026); C7 is dropped. `evaluation_harness.py --rate-variants` also scores C8 variants (Dixon-Coles penalty or season carry-over, `RATE_VARIANTS`; `scripts/c8_variants_report.py`): none replaced C8 (Phase 2g-2), and none can be declared. `DixonColesModel`'s defaults (`l2` 0.08, `season_carry_over` 1.0) must not change. C8 was scored once on the holdout against C6 on 17 Nov 2026 (`evaluation/declarations/c8_holdout.json`, `evaluation/holdout_c8/`): no release, because the away calibration slope failed. It is locked in the ledger; nothing live changed (plan Phase 2g-3). Next research candidate (Paul, 17 Nov 2026; not built yet): C8 plus a walk-forward calibration slope fitted on development data only. It is declared against C6 before any domestic match played after 10 Oct 2026 is read, and scored once when at least 300 such domestic fixtures with prices exist (plan Phase 2g-4). Compared with C6 in `evaluation/c7_c8_rate_calibration/` (`scripts/c7_c8_report.py`; `docs/plan.md`, Phase 2g).
- `evaluation_diagnostics.py`: the standing diagnostics a locked harness run writes (`diagnostics.json`; saved report in `evaluation/diagnostics/`): research baselines C0 and DC, de-vigged quote references QPROP and QPOW, the disagreement test (p ∝ M^a · R^b), fixed segments for the gap to M and return by odds band. Reporting only; definitions fixed 15 Nov 2026 (`docs/plan.md`, "How each change is judged"). C0, DC, QPROP and QPOW are yardsticks, never declared candidates.
- `.football_cache/`: historical football-data.co.uk files (Pinnacle prices end 15 Jan 2026; Bet365 continues).
